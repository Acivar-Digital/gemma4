# SFT Data Audit, Sufficiency Analysis & Dataset Builder Fixes

## 1. Quantitative Audit of `training/sft_data/unsloth_sft_*.jsonl`

We audited the existing SFT dataset (`training/sft_data/unsloth_sft_train.jsonl` and `training/sft_data/unsloth_sft_val.jsonl`) generated by `scripts/build_unsloth_dataset.py` from verified resolved teacher trajectories (`results/run_B40` and `results/run_B39`).

### 1.1 Dataset Volume & Trajectory Provenance
- **Source Runs**: `results/run_B40` (`50/77` resolved) and `results/run_B39` (`56/129` resolved), executed using our exact 5-Skill + 5-Tool contract on the LiteRouter frontier teacher (`stealth/space-bunny-alpha`).
- **Trajectory Filtering**: After filtering out non-surgical patches (`> 150` diff lines), high-turn flailing runs (`tool_calls > 35`), banned meta-tools (`load_skill`, `list_skills`, `load_skill_resource`), and near-duplicate patches (`> 90%` `difflib` similarity), **`40` unique resolved teacher trajectories** remain.
- **Window Slicing**: Each trajectory is sliced into compact multi-turn decision windows (`[system, user, prev_assistant, prev_tool_response, target_assistant]`), yielding **`1,107` total rows**:
  - `training/sft_data/unsloth_sft_train.jsonl`: **`885` windows**
  - `training/sft_data/unsloth_sft_val.jsonl`: **`222` windows**

## 2. Four Actual Bugs in `scripts/build_unsloth_dataset.py` & Exact Code Fixes

While the underlying teacher trajectories and 5-skill tool distribution are sound, our audit of `scripts/build_unsloth_dataset.py` identified **four concrete bugs** that must be fixed before running Track 2 Unsloth LoRA training.

### Bug 1: Wrong Chat Template & Control Tokens (`lines 297–325`)
- **What Is Broken**:
  `render_gemma_chat_turns()` (`scripts/build_unsloth_dataset.py:297-325`) manually formats conversations using Gemma 2/3 `<start_of_turn>` / `<end_of_turn>` tags and symmetric `<|tool_call|>call:{fn_name}{fn_args}<|tool_call|>` strings where `fn_args` is a raw JSON string (`{"skill_name": "fast-grep", ...}`):
  ```python
  # BROKEN (scripts/build_unsloth_dataset.py:306-324):
  if role == "system":
      turns.append(f"<start_of_turn>system\n{content}<end_of_turn>")
  ...
  parts.append(f"<|tool_call|>call:{fn_name}{fn_args}<|tool_call|>")
  turns.append(f"<start_of_turn>model\n{asst_body}<end_of_turn>")
  ```
  In Gemma 4 (`models/gemma-4-31b-it-qat-w4a16-ct/`), `<start_of_turn>` is not the turn delimiter (`<|turn>` ID `105` / `<turn|>` ID `106`), the tool-call closer is asymmetric (`<tool_call|>` ID `49`, not `<|tool_call|>`), tool arguments use unquoted sorted keys with `<|"|>` (ID `52`) string delimiters, and thoughts must live in `message["reasoning"]` inside `<|channel>thought\n...<channel|>` (IDs `100`/`101`) rather than `message["content"]` (where `chat_template.jinja:326` `strip_thinking()` deletes them).
- **Exact Fix**:
  Delete `render_gemma_chat_turns()` completely. Parse `tc["function"]["arguments"]` into a Python `dict`, move assistant thought text into `msg["reasoning"]` (initializing a brief deterministic reasoning string if empty on Turn 2+ so `chat_template.jinja:241` matches line `388`), and render both `prefix_text` (`add_generation_prompt=True`) and `full_text` (`add_generation_prompt=False`) exclusively via `tokenizer.apply_chat_template(..., enable_thinking=True, preserve_thinking=True)` with `assert full_text.startswith(prefix_text)`.

### Bug 2: `289/885` (`32.66%`) Dead-Thought Windows (`target_tools: []`) (`lines 250–293`)
- **What Is Broken**:
  In `slice_trajectory_decisions()` (`scripts/build_unsloth_dataset.py:250-293`), every assistant message in the trace becomes a standalone supervised training target — even when the teacher emitted an intermediate thought-only turn with `tool_calls == []` (`289/885 = 32.66%` of train rows). Training on `target_tools: []` windows supervises the model to emit `<turn|>\n` (EOS) right after a thought **without calling any tool**, teaching premature turn termination during inference.
- **Exact Fix**:
  Before slicing windows, run a trajectory normalizer that **merges consecutive thought-only assistant turns** into the `reasoning` field of the immediately following tool-calling assistant turn, and **drops any trailing orphan thought-only turns** that have no subsequent tool call. Every remaining training window (`596` train windows) is guaranteed to have `len(target_tools) >= 1` and end with a valid `<|tool_call>...<tool_call|><|tool_response>` boundary.

### Bug 3: `100%` `task_id` Leakage Between Train and Validation Splits (`lines 475–490`)
- **What Is Broken**:
  `scripts/build_unsloth_dataset.py:475-490` groups individual decision windows (`all_decision_samples`) by `row["repo"]` and randomly shuffles windows before taking an 80/20 split:
  ```python
  # BROKEN (scripts/build_unsloth_dataset.py:483-487):
  for repo, rows in sorted(repo_groups.items()):
      random.shuffle(rows)
      val_count = max(1, int(round(len(rows) * VAL_RATIO))) ...
  ```
  Because each of the 40 trajectories produces ~22 windows, shuffling at the window level places windows from the **exact same `task_id`** into both `unsloth_sft_train.jsonl` and `unsloth_sft_val.jsonl` (`40/40 = 100%` `task_id` overlap). Validation loss therefore measures intra-trajectory memorization rather than cross-task generalization.
- **Exact Fix**:
  Group decision windows by **`(repo, task_id)`** first, shuffle the unique `task_id`s within each repository (`SEED = 42`), and assign whole `task_id`s to either Train (`34` tasks) or Validation (`6` held-out tasks: e.g., `3` FastAPI, `2` Rich, `1` Requests), asserting `assert set(train_task_ids).isdisjoint(set(val_task_ids))` before writing JSONL files.

### Bug 4: 3-Line Stub `SYSTEM_PROMPT` Instead of Production `prompts/main.md` (`lines 50–54`)
- **What Is Broken**:
  `scripts/build_unsloth_dataset.py:50-54` hardcodes a 3-line placeholder system prompt:
  ```python
  SYSTEM_PROMPT = (
      "You are the Autonomous Software Developer fixing Python defects in /workspace.\n"
      "Tools: read_file, edit_file, write_file, get_status, submit_patch.\n"
      "Skills: fast-grep, code-map, code-oracle, repro-check, test-gate."
  )
  ```
  At inference time on Kaggle, the agent receives `submissions/track1_live/prompts/main.md` (which defines the 40-call budget ladder, the 3-bullet scratchpad `FILES EXAMINED / ROOT CAUSE FOUND / DO NOT RE-READ`, and the plain-text parameter schemas for all 5 skills). Training on a 3-line stub creates a train-test system prompt mismatch.
- **Exact Fix**:
  Load `SYSTEM_PROMPT = (ROOT_DIR / "submissions" / "track1_live" / "prompts" / "main.md").read_text(encoding="utf-8").strip()` directly in `scripts/build_unsloth_dataset.py` so every training window is conditioned on the exact production system prompt.

## 3. Summary of Dataset State Before vs. After Fixes

| Dataset Property | Current (`unsloth_sft_train.jsonl`) | Post-Fix (`build_unsloth_dataset.py` v2) |
| :--- | :--- | :--- |
| **Chat Template** | Broken `<start_of_turn>` + symmetric `<|tool_call|>` | Official Gemma 4 `chat_template.jinja` (`<|turn>`, `<|channel>thought\n`, `<|"|>`, `<tool_call|>`) |
| **Loss Masking** | Unmasked full-string `text` | Prefix-delta masking (`full_text[len(prefix_text):]`) with Turn 2+ non-empty `reasoning` guard |
| **Dead-Thought Rows (`target_tools: []`)** | `289 / 885` (`32.66%`) | **`0 / 596` (`0.0%`)** — merged into next action turn's `reasoning` |

| **Max Sequence Length** | `2,822` tokens (`0%` truncated at `3072`) | ~`3,032` tokens (`0%` truncated at `3072`) |
| **`run_command` Calls** | `0` (`0.0%`) | **`0` (`0.0%`)** — strictly 5-Skill + 5-Tool contract |
