## 1. Executive Summary & Context

The goal is to produce a defect-free, 1,500-task multi-turn SFT dataset for fine-tuning the Gemma 4 31B IT base model (`google/gemma-4-31b-it-qat-w4a16-ct` / `google/gemma-4-31B-it-qat-q4_0-unquantized`) on a single 24GB L4 GPU via Unsloth.

Earlier heuristic datasets generated by `scripts/sft_data_filters.py` had 5 fatal defects (0 calls to `code-map` and `code-oracle`, broken regexes in `fast-grep` and `repro-check`, synthetic 9-line prompt mismatch, right-truncation `loss=0.0` masking bug on GCP, and too few unique tasks). To solve this, we decoupled the task qualification extraction from the translation agent, built a Pydantic AI 2.0 (`pydantic-ai 2.54.0`) + `pydantic_graph (1.63.0)` translation DAG, and extracted a gold candidate set of qualified tasks.

### B. Translation DAG (`pydantic/translate_sft_dag.py`)
- **Architecture:** 5-node `pydantic_graph` topology:
  - `IngestRawTaskNode`: Ingests candidate JSONL records and validates constraints.
  - `RunPydanticAgentNode`: Pydantic AI 2.0 translation agent (`thinkingmachines/inkling:free` on LiteRouter) enforcing the strict 5-tool + 5-skill schema with `extra="forbid"`.
  - `ReconcileObservationsNode`: Pairs raw stdout/tracebacks to translated tools, serializing `arguments` as Python `dict` mappings (NOT JSON strings) to satisfy Gemma 4 `chat_template.jinja:258`.
  - `RenderGemma4JinjaNode`: Evaluates `enable_thinking=False` template, enforcing left-truncation prefix-delta masking (`input_ids` len $\le 3072$, zero thought tokens, completion starting with `<|tool_call>call:`).
  - `PersistTaskArtifactsNode` / `PersistRejectionNode`: Flushes completed tasks atomically with `os.fsync` to `pydantic/output/` and appends rejected tasks to `pydantic/output/rejected_tasks.jsonl`.
- **Unit Tests:** `pydantic/test_translate_sft_dag.py` (**4/4 passing in ~11s**).
- **Documentation:** `pydantic/README.md`.
